# 地圖網站（T11 v1、T12 地圖指令、T15m 行程與建議 UI 原型）

伊勢志摩旅遊規劃的地圖網站，**手機優先**（家人多半在 LINE 內建瀏覽器打開）。設計見 [interaction-design.md](../docs/interaction-design.md)，技術與 store 的形狀見 [architecture.md](../docs/architecture.md) §2。

技術：Vite + React + TypeScript + MapLibre GL + Zustand，圖磚用 [OpenFreeMap](https://openfreemap.org/)（免費、不需要 key）。

## 啟動

需要 Node 22。`web` 是 npm workspaces 的一員（`@travel-helper/web`），**在專案根目錄**安裝和執行：

```sh
npm install        # 在根目錄跑一次就好
npm run dev        # 開發伺服器（預設 http://localhost:5173）
npm run dev -- --host   # 手機上看：用手機開終端機印出的區網網址
```

其他指令（在根目錄跑）：

```sh
npm test                       # 單元測試（含 web/test/）
npm run e2e                    # Playwright：主要流程，手機（390px）和電腦各跑一次；第一次要先 npx playwright install chromium
npm run typecheck              # 所有 workspace 的 tsc
npm run build                  # tsc + vite build，輸出到 web/dist/
npm run preview -w web         # 預覽 build 的結果
```

加套件：`npm install <套件> -w web`。共用的型別從 `@travel-helper/engine/types` import；engine 還沒有的先放在 `src/data/types.ts`。

## 假後端、假登入（T15m，只在 dev server）

T15、T16 接上 Worker 之前，`npm run dev` 用假後端（`src/backend/mock.ts`，資料存在瀏覽器的 localStorage）和種子資料（`src/dev-fixtures/seed.ts`：4 位假家人、排了一半的行程、❤️／👎、留言、候選、預約筆記、修改紀錄）。上方列右邊的「我」點了是開發用選單：

- **切換使用者**：看別人的留言、試「只有寫的人能改刪」、❤️ 的頭像。
- **假裝別人改了行程**：下次存檔會出現「別人改過了」。
- **重設假資料**／**重設成只有航班的行程**。
- **編輯閒置**：改成 1 分鐘可以試自動結束編輯。

給 👤 檢視的截圖：先 `npm run dev -- --port 5191`，再 `node web/e2e/shots.mjs`，手機和電腦各一組放在 `data/cache/work/t15m/`；電腦版版面（1600、1280 寬）用 `node web/e2e/shots-layout.mjs`，放在 `data/cache/work/t15m-layout/`；第三輪（這一天一般／規劃模式、多點卡片、交通細列、留言、預約筆記、想去的卡片和月曆，1600、1280、390 寬）用 `node web/e2e/shots-round3.mjs`，放在 `data/cache/work/t15m-round3/`；第四輪用 `node web/e2e/shots-round4.mjs`，放在 `data/cache/work/t15m-round4/`；**第五輪**（2/3 時間軸、時間條、編輯中的藍條、2/4 交通卡編輯／班次下拉／收起／展開、班次表、候選一般／編輯中、地圖彈窗、整趟 4 色和點某天的路線，1600、1280、390 寬）用 `node web/e2e/shots-round5.mjs`，放在 `data/cache/work/t15m-round5/`。**第六輪**（網頁版 1280：標籤彈窗、⋯ 選單、重疊卡選單、移到第幾天、詳情的問 AI；手機 390：探索、詳情、想去、行程中間高度、點卡片、編輯的動作面板、AI 分頁、半屏聊天、整趟、我）用 `node web/e2e/shots-round6.mjs`，放在 `data/cache/work/t15m-round6/`。第三、四輪的腳本只改到跑得完，畫面以第五輪為準；第六輪重做了手機版，舊腳本（含第五輪）的手機部分不一定跑得完，手機畫面以第六輪為準。截圖腳本和 e2e 一樣擋掉 OSRM（距離是直線），種子資料的 2/4 伊雜宮 → 大王埼燈塔「自動」是計程車，腳本先在編輯中改成大眾運輸。

## 畫面

- **手機**（900px 以下，第六輪重做，設計見 [2026-10-25-itinerary-round6-mobile-design.md](../docs/superpowers/specs/2026-10-25-itinerary-round6-mobile-design.md)）：`App.tsx` 用 `useIsDesktop()` 分一次，手機畫 `src/mobile/MobileApp.tsx`。底部 5 個分頁「探索｜想去｜行程｜AI｜我」（`TabBar`）；沒有上方列和拉起面板。地圖（`MapView`）一直掛著，只有行程分頁看得到（其他分頁用 `visibility: hidden` 藏起來）。詳情、討論、預約是蓋在最上面的整頁（一次一層，打開時推一筆 history，上一頁就是關掉）。
  - 探索（`ExploreFeed`、`FeedFilters`）：兩欄圖片牆；想去（`WishlistPage`）；詳情（`PlaceDetailPage`）；我（`MePage`：討論、預約、下載 JSON）。
  - 行程（`TripPage`）：地圖上蓋一張可以拉的面板（`DaySheet`，低／中／高，`data-snap`），天數列 `DayStrip`、整趟 `TripOverview`、卡片 `MobileCard`、交通 `MobileLeg`。點卡片到中間高度、地圖飛過去；編輯中卡片的「⋯」開底部動作面板（`ActionSheet`，子畫面 `TagSheet`、`MoveDaySheet`）。
  - AI：`ChatPage`（分頁）和 `ChatSheet`（行程頁的半屏），共用 `ChatView`；內容先是 `chatDemo.ts` 的假訊息，T16m 接上。詳情的「問 AI」透過 `uiStore.chatDraft` 帶進來。
  - 手機版自己的狀態在 `mobile/mobileStore.ts`，樣式在 `mobile.css`、`chat.css`（class 都用 `m-` 開頭）。
  - `src/shared/`：網頁版、手機版共用的純函式（有單元測試）：`tagOptions`（標籤分組）、`cardActions`（卡片的動作清單）、`askAiPrompts`（問 AI 的建議問題）、`placeLists`、`exportJson`。
- **電腦**：三欄（參考 puma.taipei/heart-island）。聊天室在左（T16 才做，先留位置）；中間是地圖，日期列、「我」浮在地圖上方，篩選標籤在日期下面；右側一欄頂到最上面，分頁「探索｜想去｜行程」，點了探索的卡片，詳情蓋在這一欄上（「← 返回」）。判斷電腦版用 `DESKTOP_QUERY`（`hooks.ts`，900px）。
- **日期列（第三輪）**：「全部」和每一天的分頁，右邊是整趟的工具：💬 留言、📋 預約筆記（旁邊的數字是還沒訂位的筆數）、⋯（匯出 JSON）。💬、📋 打開地圖區的視窗（`MapPanel`，`uiStore.mapPanel`），上面可切「這天｜整趟」，視窗開著時日期列的按鈕還按得到。整趟的留言是對 `trip` 這個目標的留言；預約筆記每列有「未訂位／已訂位／不訂位」、備註（打完字按 Enter 或移開就存，不會蓋掉狀態），住宿多一個晚數。時間軸上的預約 tag（未訂位橘色、已訂位 ✓ 綠色、不訂位不顯示）點了回到那一列。
- **地圖**：像 Google Maps 的類別圖標（車站藍🚃、景點綠📷、住宿紫🛏、餐廳橘🍴）；縮小時是小點，放大到 12 以上換成圖標、13 以上寫名稱；S 級明顯大、B 級小。選中的點（打開詳情、點了跳到探索卡片的那個）換成水滴形的大圖釘。選了某一天，那天的點換成那天顏色的編號圓（起點、終點的住宿「宿」、機場「機」、其他 1、2、3…，和時間軸的編號一樣），路線有方向箭頭；其他天的點變淡（不隱藏），不符合篩選的也變淡。
- **小卡片**：電腦滑鼠移上去、手機點一下。手機再點一下小卡片才開詳情；電腦點地圖上的點（或小卡片），右側切到探索、捲到那張卡片，再點卡片才開詳情。
- **問 AI**：把地點帶進聊天（加進選取，T16 的聊天室再用）。電腦版把探索的卡片、詳情的標題拖到左邊的聊天室（拖著時聊天室亮起來）；手機沒有拖曳，按照片上的「＋ AI」或詳情的「＋ 問 AI」，聊天分頁顯示帶了幾個點。地圖上的點不能拖（會和拖地圖衝突），從地圖開始是先點點跳到探索卡片。
- **詳情面板**：最上面一列是「← 返回」（電腦版；手機是右邊的 ✕）、「問 AI」（先放進選取，T16 再用），規劃模式下多一個「📅 排進行程」。標題列是分級徽章（S 金、A 銀、B 銅）、名稱、❤️／👎 的數量（移上去看是誰按的；❤️ 就是想去，按了出現在「❤️ 想去」）。下面分四頁：總覽（首張照片、評分、介紹、價格、已排在哪幾天（含備選）；評分平常只看到 Google、食べログ，展開看其他網站和我們的五項評分）、詳細（住宿、團體、長輩小孩、營業時間）、附近・連結（附近、連結、來源；點附近的地點，地圖移過去、點會閃）、圖片。一打開不用捲就看得到介紹。改過的欄位標「已修改（誰、何時）」，點了看修改紀錄、原本的值，自己的可以復原。
- **行程分頁（第三輪）**：兩層。「全部」（或按「← 整趟」）是整趟的總覽，每天一列（日期、去哪幾個點、住哪、⚠ 數、候選數），點一天進去；選了某一天是那天的頁面，只放這一天的東西：標題（日期、‹ ›、問 AI、規劃模式按鈕）、一行摘要（幾點出發、幾點回住宿、交通多久〔含緩衝〕、⚠ 數字，點了才展開）、一條按時間比例的橫條、時間軸、這天的候選。整趟才用得到的（留言、預約、匯出）都在日期列。
- **時間軸卡片（第三輪）**：一般模式只看：開始時間（固定時間標 📌）、名稱、停留時間、頭像（按 ❤️ 的人，疊最多 4 個，其他寫「+N」，點了展開名單）、用餐 tag（早餐／午餐／晚餐／點心）、吃法 tag（全員一起／分開吃）、預約 tag、備註（唯讀）、⚠。規劃模式多：停留 −／＋、標籤（點了選用餐和吃法，不標就不顯示，不強制排餐）、「⋯」選單（移到第 _ 天、移進／移出分組、拿掉）。一張卡片可以放好幾個點：有「＋N」，展開叫「這個時段也可以去」，主要的排第一，規劃模式可以「設為主要」、「從這張卡片拿掉」（回到這天的候選）；候選上的「併到…」選一張卡片放進去。住宿卡片寫含餐 tag（含早餐、含晚餐），規劃模式有「換住宿」，打開想去的住宿，按「設為 _ 的住宿」。
- **交通細列（第三輪）**：卡片之間是「🚕 39 分＋緩衝 10 分」。點一下展開（一次只開一段）：交通方式、分鐘、距離（沿道路／直線）、轉乘、緩衝、備註和「在 Google Maps 開路線」連結，地圖只亮那一段、其他天和其他段的行程線變淡（`uiStore.legOpen`；換天、回整趟、換分頁時自動收起）。搭電車、巴士、船的段落照班次畫：起點到上車的站、每一程（電車沿車站）、轉乘的兩站之間、下車的站到終點，每一程上下車的站亮起來（整天的行程線也一樣）。規劃模式可以改方式（自動、步行、計程車、電車、巴士、船、包車、自駕、其他）、分鐘（清空回到自動）、緩衝（每次 ±5 分，預設全員 10、分組 5，改過寫「已調整」，調回預設的值或按恢復預設就是「預設」）、備註；每個改動後面的時間跟著動，遇到固定時間的項目就由等待時間吸收。一天最後回住宿的那段交通也一樣。
- **❤️ 想去**：電腦版右欄第二個分頁、手機下方面板的分頁。和探索一樣（類型、地區、篩選、搜尋、排序、大照片／只有文字），只列有人按 ❤️ 的點，地圖上其他點變淡。卡片的照片右上角一直有 ❤️／👎（顯示人數，▾ 看是誰按的），照片左上角是類型和「候選 2/5」「✓ 已排 2/10」tag，底下是「加到某天」（展開是 2/2～2/13 的月曆，已加的日期打勾，再點一次拿掉；別人加的候選，非規劃模式不能從月曆拿掉）、留言（收起來，只有一層，自己的可以改刪）。點卡片看詳情，返回鈕寫「返回想去」。
- **這天的候選、這天的留言（T15m）**：行程分頁時間軸下面。候選是在想去或探索「加到某天」的點（頭像看是誰按的；已經排進這天的不列），點一筆地圖飛過去、跳出小卡片；自己加的可以撤回；規劃模式下每筆有 ↑（排進）、「併到…」（放進某張卡片）、「拿掉」。這天的留言是對這天行程的討論。
- **第五輪（設計見 [2026-10-25-itinerary-round5-design.md](../docs/superpowers/specs/2026-10-25-itinerary-round5-design.md)，和上面衝突時以這條為準）**：「規劃模式」改叫「編輯」。時間軸是一條虛線串起資料卡（左邊類型色塊「宿／景／餐／站／機／點」、右上角類型色的編號，出發的住宿是 0、回住宿接著編，地圖同一個號碼）；停留時間固定寫「X小時MM分」；到了要等（📌 固定時間、還沒開門）合成交通卡下面一條黃色「⏳ 10:47 到，等 73 分（午餐 📌 12:00 才開始）」，沒有「空檔」列。交通卡平常收起（SVG 圖示、方式＋分鐘、第二行距離——平常就用道路路線的距離，點開前後一樣），大眾運輸點了展開步驟（步行、等車、搭車那一行），點搭車那一行在地圖那側開班次表（搭不到灰、搭得到綠、選定藍；`TimetablePopup`）；編輯中原地改方式（「自動（計程車）」寫出它選了什麼）、每一程的班次下拉只列搭得到的。時間條用類型色、等待斜紋、整點刻度。候選的標題是「候選 N」，卡片和資料卡同樣子（虛線框、沒有編號）。地圖彈窗變大、永遠在最上層；每天的路線 4 色輪流，整趟點某天的路線其他天變淡。
- **編輯（T15m，第五輪前叫規劃模式）**：日期列右邊藍色的「✏️ 編輯這天」，進入前確認（「開始編輯？」），時間軸面板最上面是藍條（快照、完成），面板不在畫面上時地圖上方有精簡的「✏️ 編輯中・完成」；換天照樣在編輯，選「全部」就結束；10 分鐘沒動作自動結束。這天的候選每筆多一個 ↑（插在這天最順路的位置，排進後從候選消失；住宿是設成那晚的住宿，先確認）、「併到…」和「拿掉」（別人加的，要寫理由，理由變成那個點的一則〔不採用〕留言）。時間軸的卡片電腦版用拖的換順序、手機長按後拖；停留時間 −15／＋15、點開始時間切換固定時間、標籤、「⋯」選單、交通細列的設定（見上）。每次修改前自動存快照，可以復原。別人先改過時存不了，會提示重新載入。
- **探索**：電腦版是右側的「探索」分頁：餐廳／住宿／景點是最上層、一直黏在上面；底下選地區（再細分小區域）、常用篩選一排（含「只列地圖畫面裡的」）、其他在「更多篩選」；可以依推薦、評分、❤️ 排序。往下捲時篩選收合成一列摘要（例如「鳥羽・午餐」，旁邊是筆數、排序、顯示方式），點摘要在原地展開；顯示方式可以切換大照片或只有文字。滑鼠移上去地圖上的點會閃，點了地圖移過去、打開詳情；反過來點地圖上的點，清單跳到那張卡片。手機還是圖片牆：只放目前地圖畫面裡、符合篩選的點，S 大一倍、A 正常、B 小張；移動地圖跟著換。照片和地圖互相連動（滑鼠移上去或點一下照片，地圖上的點會閃）。 探索的卡片和想去一樣：照片右上角 ❤️／👎 一直都在，左上角有候選、已排的 tag；「加到某天」開月曆，選了日期就順手按 ❤️（原本是 👎 會換成 ❤️）。
- **車站面板**：車站的詳情裡有時刻表：選日期（自動判斷平日／土休日）和時間，顯示上下行前 2 班、後 4 班，附 Google Maps 路線和ジョルダン的連結。
- **地圖指令（T12）**：UI 和之後 T16 的 AI 都透過 `src/commands.ts` 操作地圖（`focus`、`highlight`、`drawRoute`、`compare`、`clearHighlights`、`selectDay`、`setFilter`／`clearFilter`、`select`／`unselect`、`showProposal`／`clearProposal`、`getViewState`），說明在 architecture §2「地圖指令」。地圖上方會出現說明列：AI 的提議（虛線、半透明）、比較（A、B、C）、標示和路線（可以清掉）。
- **路線**：步行、車沿道路走，在瀏覽器查公開的 OSRM（`routing.openstreetmap.de`），查過的存在 localStorage，查失敗的 10 分鐘內不重查；電車依序連車站；查不到畫直線。確定的行程線每一天都沿道路畫（選定那天優先，`src/itineraryRoutes.ts`，查到就讓 `routesVersion` 加一、地圖重畫）。時間用 engine 的預設速度算（`src/lib/routing.ts`）。
- **資料檢查頁**：網址加 `?check` 是 v0 的檢查工具（座標、ID、來源的問題、各區筆數、bbox 框線），程式在 `src/v0/`，新增區域蒐集資料時用。

## 資料從哪裡來

- 資料存取包在 `src/data/` 的介面後面（`DataSource`）。現在是本機的實作 `local.ts`：build 時用 `import.meta.glob` 讀 `data/areas/*/*.json`、`data/stations.json`、`data/areas.json`；時刻表（`data/timetables/kintetsu/`、`jr/`）照車站拆開，用到才載入。研究筆記（`raw/`）、`cache/`、`derived/` 不打包。T15 改成 API 時只換 `src/data/index.ts` 那一行。
- **區域不寫死**：區域清單、名稱、子地區、篩選的選項、初始範圍都從 `areas.json` 和資料來。新增區域時把資料放進 `data/areas/<新區域>/`、`areas.json` 加上這一區，重新 build 就會出現。
- **代表照片**是 `photos` 的第一張（T21 排好）。打不開時依序換下一張，全部打不開就顯示類別色的替代圖；Wikimedia 的原圖改用 800px 縮圖網址；不送 referrer。
- **楽天**的資料（評分、價格、照片）在詳情面板下方附「Supported by Rakuten Developers」。
- **假行程**（`src/dev-fixtures/itinerary.json`，engine 的 itinerary-v1）只在 dev server 載入，用來試天數分頁、提議的顯示；篩選面板最下面可以關掉。正式 build 不帶。T15 換成確定的行程。

## 測試和畫面檢查用的掛勾

dev server 下 `window.__th` 有 `map`（MapLibre）、`appStore`、`dataStore`、`commands`（地圖指令）、`visual(id)`，Playwright 用它算點的像素位置、讀狀態、下指令（`e2e/commands.spec.ts`，OSRM 用假的回應）；正式 build 沒有。設 `TH_SHOTS=<目錄>` 跑 `npm run e2e` 會順便拍標示、路線、比較、提議的截圖。

## 備註

- maplibre-gl v6 的 worker 是另一個檔案，`MapView.tsx` 用 `?worker&url` 讓 Vite 打包，再用 `setWorkerUrl` 指定。
- 瀏覽器 console 裡 `highway-shield…filter`、`Image "…" could not be loaded` 的警告來自 OpenFreeMap 的樣式本身，不影響使用。
- 地圖一律朝北（關掉旋轉），手機上兩指縮放比較不會誤觸。
