# 讀文 subagent 的指令範本（筆記 dossier）

主 session 每個資料點開一個 subagent（`general-purpose`），把下面的範本填好當作 prompt。規則見 CONVENTIONS.md §4「讀文與筆記」。

---

你負責**一個資料點**的讀文工作。只讀網頁、寫一個筆記檔，不改其他檔案。

- 資料點：`{id}`（{類型：景點／住宿／餐廳}），{日文名稱}／{中文名稱}，{地址或子地區}
- 專案：`{repo 路徑}`。**不用讀 CONVENTIONS.md**，這份指令就是全部規則（省 context）。
- 這個類型評分會看的面向（主 session 從 CONVENTIONS §5.1 貼上該類型的表格那幾行）：{例如餐廳：推薦度、在地特色、15 人、長輩、小孩}；筆記要盡量涵蓋這些面向
- 已知的來源（主 session 給的）：{URL 清單，例如官網、觀光協會頁、候選清單 `mentions` 裡的文章和 highlight}
- 要補找的心得：用 WebSearch 找 {2～4} 篇，關鍵字照 CONVENTIONS §4 的範本（日文優先，中文找部落格心得）
- **要回填的事實欄位**（只填來源寫明的，不知道就寫 null）：{例如 hours、fares、accessibility、group、kids、febNote、closures 的欄位清單}

規則：
1. 只用 WebSearch、WebFetch。**不要用 Claude in Chrome**（只有一個瀏覽器，由主 session 用）；食べログ、Google Maps 不要讀（用程式讀會被擋，主 session 會用 Chrome 查）。
2. 每個來源只讀需要的部分；**不要複製原文**，用繁體中文寫重點（菜名、專有名詞附日文原文）。
3. 文章太舊（例如 5 年以上）或明顯是業配，照樣記，但標出來。
4. 不同來源互相矛盾時，兩邊都記，標「衝突」。

輸出：
- **寫檔**：`data/raw/{area}/dossiers/{id}.md`，格式照下面，**40 行以內**。
- **回覆主 session**（不要超過 30 行）：
  1. 一行結論（例如「讀了 4 篇，冬季評價好，長階梯多」）
  2. 要回填的事實欄位，用 JSON（只放有來源的欄位，每個欄位附來源 URL）
  3. 要加進 `sources` 的項目，用 JSON 陣列（`type`、`url`、`retrieved`、`note`：這篇的重點一句）

筆記格式：
```markdown
# {id} {日文名稱}／{中文名稱}

- 讀文日期：YYYY-MM-DD
- 來源：
  1. [類型] 標題（日期）URL
  2. ...

## 重點
- [推薦] 冬季限定的牡蠣吃到飽，多篇都說值得專程去（1、3）
- [缺點] 週末中午排隊 1 小時以上（2）
- [團體] 有 30 人的包廂，要電話預約（官網）
- [長輩] 入口有 10 階左右的樓梯，店內是椅子座位（3）
- [小孩] 有兒童套餐（1）
- [招牌] 伊勢龍蝦炸物定食（伊勢海老フライ定食）2,800 円，3 篇都推薦（1、2、3）
- [冬季] 2 月照常營業（官網）
- [交通] 鳥羽站步行 10 分，有停車場（1）

## 衝突、待確認
- 營業時間：官網 11:00～、部落格 10:30～（2，2019 年舊文）

## 資料量
- 心得 3 篇（日 2、中 1）；最新一篇 2025-11
```
標籤固定用：`[推薦]` `[缺點]` `[團體]` `[長輩]` `[小孩]` `[冬季]` `[交通]` `[價格]` `[招牌]` `[其他]`；每條後面用括號標來源編號。`[招牌]` 只用在餐廳（或有餐飲的景點、住宿的料理）：招牌菜附日文名稱，來源有寫價格就記；不要抄完整菜單。
