# 角色 3（對照組：排行程的主辦人）基準情境紀錄

情境：「把 2/6 的晚餐換成浦村的一家牡蠣店，確認走法和時間，順手看一下那天有沒有待訂的事。」
走訪日期：2026-11-06。截圖都在 `shots/`（下面只寫檔名）。GIF 由瀏覽器下載（`role3-mobile.gif`、`role3-desktop.gif`，在瀏覽器的下載資料夾）。

先講兩件走之前不知道、走了才發現的事（影響怎麼算「換」）：
- **2/6 本來沒有排晚餐**：09:30 鳥羽國際飯店出發 → 神明神社 → 海女小屋 八幡竈（午餐）→ 海之博物館 → 14:05 到住宿 大田家 HEALING STAY（待訂）。整趟那列寫「待訂 · 晚餐未選」。所以「換晚餐」實際做的是「把浦村的牡蠣店排進 2/6」。
- **浦村只有一家牡蠣店在資料裡**：搜「浦村」得 3 個點（悠季之里、英治丸、CaroCaro 鐵板），牡蠣店只有 **英治丸（烤牡蠣小屋）**，營業 9:00～15:00、不接受預約。引擎把它排在 13:40–14:55（海之博物館之後），不是晚餐時段；要當晚餐這家根本開不了。兩個版面都照做、照記。
- 手機版做完後到電腦版前照指示清了 localStorage；電腦版打開時 2/6 回到原本（沒有英治丸、候選 2），兩個版面因此是同一個起點。

## 「換好了」的回饋、家人看不看得到

- **手機**：「排進這天」之後畫面直接變（第 4 站出現、時間軸重算、地圖多一個標），**沒有任何文字說「已儲存」**；「加到某天 → 好」之後也沒看到提示（截圖 72 只有想去數字變了）。按「完成」也沒有訊息。整趟列會變成「相差 → 浦村」，但沒有版本／誰改的那一行。整個流程裡唯一提到「大家」的是進編輯前的確認「修改大家共用的那一份行程」。
- **電腦**：兩個明確的提示——「✓ 已加到 2/6 的候選」（詳情彈窗左上）、「✓ 已儲存：2/6：＋英治丸（烤牡蠣小屋）」（地圖頂端，寫出哪天、加了什麼）。整趟行程標題下有「第 1 版 · 我 11/6 02:18 改的」（誰、何時）。都沒有一句寫「家人會看到」；要靠「大家共用的那一份」那句和版本列推。
- 附帶：手機改完、清 localStorage 之後電腦版回到原本的行程，表示這個開發環境的行程改動存在本機，不是家人共用的那份（只記不評）。

## 「待訂」在哪裡、要幾步

- **手機**：
  - 日程本身：住宿卡上的墨色外框膠囊「待訂」——從換晚餐的畫面捲到底就看得到，**0 步**。
  - 整趟：2/6 列「待訂 · 晚餐未選」——**1 步**（點「整趟」）。
  - 這天的提醒清單（摘要列「⚠ 1 ∨」）**不列待訂**；再點日期晶片不會開東西。
  - 「我」分頁 → 預約筆記：沒走，照畫面應是 2 步。
- **電腦**：
  - 日程住宿卡「待訂」——**0 步**（完成編輯後就在畫面裡）。
  - 整趟 2/6 列——**1 步**（點「整趟」晶片）。
  - 頭像選單「預約筆記 8 待訂」——**1 步**（再 1 步進預約筆記）。
  - 2/6 晶片上的紅點是「要處理的提醒」（英治丸不接受預約），不是待訂。

## 設計意圖對照（只讀了 interaction-design.md 行程／日程／交通／預約相關的節）

- §4 詳情（行 137、149）：「動作列是想去 N、不喜歡 N、加到某天，**編輯中從行程打開時多『排進這天』**」「編輯中多一個『排進行程』」。實際：從探索開的詳情在編輯中仍只有「加到某天」（電腦步驟 11 證實），所以「編輯 → 探索 → 排進」這條設計上存在的捷徑走不到，只能走候選。文件寫的「從行程打開時」和我走的「從探索打開」不同，實作和文件字面上一致，但對這個情境沒有幫助。
- §6／§17.4／§25：「♡ 想去 › 候選（加到某天）› 行程（編輯時排進去）」三段式。實際完全照這條走：加到某天 → 編輯 → 候選列排進。兩個版面都一樣，所以步數差不多（16 vs 15 必要）。
- §11 手動選單：「行程項目的刪除、移到第 _ 天、調整順序」；實際候選的 ⋯ 是「排進這天／移到第幾天…／刪除」，電腦多了直接的「↑ 排進」「撤回／拿掉」鈕，比文件寫的少一層。
- §13.6 交通卡：「編輯中直接改：點交通那一行就是編輯器，拿掉『改』和『完成』；網頁再點一次收起；手機是底部面板，點 ✕、暗處或 Esc 關；收合兩行『方式＋分鐘＋⚠』」。實際一致：手機底部面板、電腦原地展開，分段鈕＋「巴士一小時一班，改搭計程車」＋備註。完成編輯後電腦版的交通卡還留著展開（文件寫「進入編輯時開著的交通會先收起」，沒寫離開時）。
- §14.2／§34.3 待訂：「墨色外框膠囊，行程卡、整趟骨架、預約一覽、頭像選單的『N 待訂』都一樣」。實際一致；整趟那格的「待訂 · 晚餐未選」也和 §34 寫的「住宿晚餐未選放整趟骨架住宿那格」一樣。
- §34 提醒：「日期列點開列整天的（手機也看得到字）」。實際手機是摘要列的「⚠ 1 ∨」，不是日期晶片；我照字面點晶片猜錯一次（手機步驟 19）。清單裡只有提醒，不含待訂——和 §34「判斷標準：家人看了會不會做什麼」一致，待訂歸預約筆記。
- §17.6「採用了住宿或要訂位的餐廳之後：復原提示旁加一句『已加進預約筆記，記得自己去訂』」：英治丸不接受預約，所以這句沒出現，無法驗證。
