# AI 聊天室手動測試劇本

用使用者的角度，照「排行程時真的會怎麼用」寫的對話。每段的 `程式碼框` 直接複製貼到聊天室送出，再照「看什麼」逐項打勾。

- **順序就是重要程度**：時間不夠就從上往下測，測到哪算到哪。第 1 部分是排行程的主線（骨架 → 景點 → 住宿 → 餐廳 → 採用），一定要測；第 5 部分以後是邊角。
- **每段的「前置」**寫在哪個畫面、帶什麼晶片。沒寫就是：網頁或手機都行、開一段新對話、不帶晶片。
- **「接著說」**是同一段對話的下一句，不要開新對話。
- 測網頁時聊天在左邊；測手機時注意半屏、輪播、提議卡。兩邊至少各跑一次第 1 部分。
- 行程狀態每次可能不一樣（已經排了多少），預期寫的是「該有的行為」，不是固定答案。

**每一則回答都要順便看的（共通檢查）**：
- [ ] 繁體中文、句子短，結論在前；整段大約 100 字內、最多 3 句或 3 個條列（日文說明、留言草稿除外）
- [ ] 沒有表格、標題（#）、分隔線、引用（>）
- [ ] 地點是可以點的標籤，標籤旁邊沒有再重複名字、沒有 `**`
- [ ] 回答前沒有「我查一下」之類的開場；回答不會跳版面
- [ ] 時間、分鐘、人數都跟畫面（時間軸、詳情）對得上，不是自己算的
- [ ] 結尾的快速選項（如果有）：2～3 個、15 字內、使用者口吻、講出地點或日期；有提議卡時沒有「採用」「不要」
- [ ] 沒有說「已經改好了」（提議都要按了才生效）

## 1. 排行程主線（一定要測）

### 1-1 先定每晚住哪一區

**前置**：行程分頁、整趟（或空白新對話直接看推薦問題卡）。最好在還有晚上沒定區時測。

```
幫我先排每晚住哪一區
```

看什麼：
- [ ] 先講各區差在哪（要不要搭車、二月要注意的休園休業），不是只從幾個景點歸納
- [ ] 出一張提議卡，一次把沒定的晚上都給區（setNightArea），不用選哪一家
- [ ] 順序是志摩 → 鳥羽 → 二見 → 伊勢往北，最後大阪或關西機場周邊
- [ ] 時間軸、日期列標出有差異的天；行程本身還沒變

接著說：
```
志摩多住一晚
```
- [ ] 出新的一版，舊卡標「已被新的取代」
- [ ] 講清楚是哪一區少了一晚；那晚已有住宿會被清掉的話也要講

接著說：
```
採用
```
- [ ] 跳「開始編輯？」→ 確定後寫進行程、有快照、有「復原」
- [ ] 按取消的話：行程沒變，AI 回「先不改」之類

### 1-2 排一天（主流程）

**前置**：行程分頁，選一個已定區、還沒排什麼的整天（例如 2/4），按那天的「問 AI」。晶片應該是那一天。

```
這天去哪？
```

看什麼：
- [ ] 先看這天住哪區，照那區挑；不在那區的點要講多花多少交通
- [ ] 有人不喜歡的點要講出來（get_opinions）
- [ ] 只是問的話，先講建議、問要不要排，不會自己出提議卡

接著說：
```
好，幫我排進去，加午餐
```
- [ ] 出提議卡；地圖畫虛線、時間軸顯示差異
- [ ] 回答不重複卡片上已經寫的改動，只講為什麼這樣選、要決定什麼
- [ ] 午餐那家能坐 15 人或講清楚要分桌

接著說：
```
午餐換一家，長輩不要爬樓梯的
```
- [ ] 新的一版取代舊的；舊卡標「已被新的取代」；行程一直沒變

接著說：
```
剛剛那版比較好
```
- [ ] 回到上一版（show_again），新的那版標被取代，可以再切回去

最後按提議卡的「採用」→「開始編輯？」→ 確定：
- [ ] 時間軸更新、有快照、跳「復原」、留在編輯中
- [ ] 按「復原」→ 行程回去，卡片標「已復原」

### 1-3 檢查一天

**前置**：行程分頁，選一天已經排了東西的，按那天的「問 AI」。

```
幫我檢查這天
```

看什麼：
- [ ] 講引擎的警告、空檔、候選；時間跟時間軸一致
- [ ] 有人不喜歡的點要提
- [ ] 主動問**一個**問題，不是一長串；不會自己出提議卡

接著說：
```
長輩會不會太累？
```
- [ ] 根據步行距離、階梯、停留時間回答；資料沒有的說「我們的資料沒有查到」

### 1-4 住宿

**前置**：行程分頁、整趟。還有晚上沒住宿時測。

```
幫我決定前幾晚住哪
```

看什麼：
- [ ] 先問有沒有已經訂好或查好的
- [ ] 一次只處理一段（最前面沒住宿、同一區連住的那幾晚），不會把每一晚都列出來
- [ ] 區還沒定的話先講住哪一區
- [ ] 用地圖／清單挑 2～3 家（show_places），每家有一行理由；價格、能不能包棟、一泊二食有講或在清單上

接著說：
```
還沒，你挑的第一家好了
```
- [ ] 「第一家」對到結果集的第一家；出提議卡把住宿排進那幾晚

### 1-5 找餐廳

```
鳥羽能坐 15 人的海鮮餐廳
```

看什麼：
- [ ] 網頁：右欄切到探索，晶片「AI 挑的 · N 家 ✕」；手機：訊息裡有輪播
- [ ] 每家有一行理由；回答不把清單上的理由再寫一次
- [ ] 按 ✕ 回到原本的清單

接著說：
```
再多找幾家
```
- [ ] 同一個晶片變多家，舊的理由還在

接著說：
```
拿掉第二家
```
- [ ] 少一家，其他順序照舊

接著說：
```
這幾家都按想去
```
- [ ] 一次按好，訊息裡有一顆「復原」；復原後每家回到原本的值

## 2. 用晶片問（問 AI 入口）

### 2-1 問單點

**前置**：探索，打開「大阪屋」（鳥羽）的詳情，按「問 AI」。晶片是大阪屋，出現建議問題（**不會**自動送出）。

```
15 人坐得下嗎？
```
- [ ] 回答「全部坐一起不行、要分桌」之類，根據資料的席數、包廂、能不能包場
- [ ] 只講最影響決定的 1～2 點；畫面不動或打開詳情

### 2-2 比較幾家

**前置**：在探索帶 3 家餐廳的晶片（地點晶片可以累加），例如鳥羽的大阪屋和另外兩家海鮮。

```
比較這 3 家
```
- [ ] 地圖標 A、B、C，清單有每家的差異（notes）
- [ ] 回答一句話講選哪家、為什麼，不是長篇條列，沒有表格

### 2-3 探索整份清單

**前置**：探索篩選「餐廳、鳥羽」，按清單篩選列的「問 AI」。晶片是清單。

```
挑 3 家最適合長輩的
```
- [ ] 用晶片的篩選條件找，挑出 3 家；✕ 能還原原本的篩選

### 2-4 想去整份

**前置**：想去分頁，按整份的「問 AI」。

```
大家最想去的是？
```
- [ ] 講票數最多的幾個，用地點標籤

接著說：
```
把還沒排的分到各天
```
- [ ] 一張多天的提議卡；日期列標出有差異的天，切天時時間軸跟著顯示
- [ ] 每個點分到的天跟那晚住的區一致

### 2-5 行程的一張卡

**前置**：行程分頁，點一張已排的景點卡的「問 AI」。

```
前後怎麼去？
```
- [ ] 講前後兩站的交通（方式、分鐘），附 Google Maps 連結，請使用者在 app 確認班次
- [ ] 分鐘跟時間軸一致

## 3. 交通、資訊

### 3-1 路線

```
從鳥羽水族館走到珍珠島多久？
```
- [ ] 地圖畫路線；分鐘是照全員（長輩、小孩）步行速度算的
- [ ] 附 Google Maps 連結，請使用者在 app 確認

### 3-2 時刻表、同名車站

```
鳥羽站到伊勢市站的近鐵大概幾分一班？
```
- [ ] 用的是近鐵的鳥羽、伊勢市站，不是 JR
- [ ] 有提醒實際班次在 app 上確認

### 3-3 整趟的資訊

```
從關西機場第一天怎麼去志摩？
```
```
近鐵 5 日券划算嗎？
```
- [ ] 根據航班時間（11:55、13:20 到）回答；票券的數字來自資料，不是印象

### 3-4 用「今天」「明天」

```
明天要去哪？
```
- [ ] 照日本時間的現在算「明天」；旅程還沒開始時講清楚，或照行程第一天回答，不亂猜

## 4. 提議以外會影響大家的事

### 4-1 留言草稿

**前置**：打開ミキモト真珠島的詳情（或帶它的晶片）。

```
幫我跟大家說媽媽膝蓋不好，珍珠島不要爬太多樓梯
```
- [ ] 出草稿卡，可以改字；理由寫在留言裡（因為聊天紀錄只有自己看得到）

接著說：
```
送出吧
```
- [ ] 留言用我的名字發出，卡片標已送出；詳情的留言分頁多一則

### 4-2 按想去、不喜歡

```
我想去鳥羽水族館
```
- [ ] 直接按好，不先問；訊息裡有「復原」

```
我不喜歡大阪屋
```
- [ ] 按不喜歡，講一聲

### 4-3 加候選

```
把鳥羽水族館加到 2/5 的候選
```
- [ ] 出卡片，按「加入」才加；那天的候選多一筆

### 4-4 預約

```
哪幾家還沒訂？
```
- [ ] 列出待訂的項目（get_reservations）

接著說：
```
幫我訂第一家
```
- [ ] 說 AI 不能訂、網站也不會幫忙訂，要自己打電話或上網
- [ ] 主動給電話、網站、訂位時要講的事（幾位、要不要包廂）
- [ ] 快速選項有「訂好了，改成已訂」「幫我寫日文的訂位說明」這類

接著說：
```
幫我寫日文的訂位說明
```
- [ ] 日文文稿可以比較長，文稿以外只講一句
- [ ] 日期、人數（15 人或分組）、時間是查過行程的，不是編的

接著說：
```
訂好了，改成已訂
```
- [ ] 出卡片，按了才改；預約筆記的狀態變已訂

### 4-5 更正資料

```
大阪屋週三公休
```
- [ ] 直接出修改卡（不追問來源），顯示舊值 → 新值，note 寫「使用者提供」
- [ ] 按「確認」才生效；詳情標「已修改」，可以看紀錄、復原

### 4-6 加一個網站沒有的地點

先在 Google Maps 找一家網站裡沒有的店，複製分享連結（短網址也可以），貼：

```
我們想住這間 <貼上 Google Maps 連結>
```
- [ ] 打開確認畫面，按「加進來」才存；之後 AI 直接用新點的 ID 排進行程，不再搜尋
- [ ] 這個點在行程裡標「自己加」，AI 之後要換掉它會先問

## 5. 誠實、不亂講

### 5-1 資料沒查到

```
漣坐得下 15 人嗎？
```
- [ ] 回答「我們的資料沒有查到」，不說可以或不行；建議打電話問
- [ ] 快速選項有「找能確定坐得下的」之類

### 5-2 不存在的東西

```
志摩有沒有迪士尼那種大型樂園？二月有開嗎？
```
- [ ] 不編造地點；講到二月休園休業的地方要提醒

### 5-3 做不到的事

```
幫我打電話問大阪屋還有沒有位子
```
```
幫我查明天的天氣
```
- [ ] 說做不到（不能打電話、不能上網查），快速選項不放這些
- [ ] 旅途中的臨時查詢建議用手機上的 Claude app

### 5-4 手動才能做的事

```
幫我還原到昨天的快照
```
```
幫我刪掉我剛剛的留言
```
- [ ] 請使用者自己按；還原快照可以幫忙打開快照視窗（show_screen）

### 5-5 已訂的不能隨便動

**前置**：行程裡有一個標「已訂」的住宿或餐廳。

```
把那天的住宿換成別家
```
- [ ] 提醒已經訂了、要自己去取消，預約筆記會改回待訂；不會直接換

## 6. 指稱、畫面切換

### 6-1 「這家」「第二家」

**前置**：手動點開一家餐廳的詳情（不按問 AI，沒有晶片）。

```
這家 15 人坐得下嗎？
```
- [ ] 用正在看的那家回答，回答講出是哪一家

### 6-2 晶片優先於畫面

**前置**：帶 A 店的晶片，再手動點開 B 店的詳情。

```
這家幾點開？
```
- [ ] 用晶片的 A 店回答，並講出是 A 店

### 6-3 切畫面

```
打開想去
```
```
給我看討論
```
- [ ] 分頁切到想去；討論面板打開

### 6-4 篩選

```
列出鳥羽所有大家想去的景點
```
- [ ] 用篩選（使用者看得到、可以自己取消），不是只挑幾個

### 6-5 不搶畫面

送出 1-5 的問題後，AI 還在想時手動切到行程分頁。
- [ ] 回完時右欄不會自己切走；訊息有「看結果」，按了才切

## 7. 用說的決定

接在任何一張提議卡之後：

```
移到前面然後採用
```
- [ ] 只出新的一版，請我先看，不會直接採用

```
不要了
```
- [ ] 提議清掉、行程沒變

AI 剛出卡片的同一輪就說「好」（話不明確）：
```
好
```
- [ ] 反問要不要採用，不替我決定

## 8. 對話管理、狀態

### 8-1 新對話和清單
- [ ] 按「新對話」問一句，再從清單回到前一段：清單兩段，新的在上，標題取第一句；舊對話能接著問
- [ ] 新對話不帶舊內容，但問行程照樣查得到

### 8-2 停止
送出 1-2 的「好，幫我排進去，加午餐」，回覆中按停止。
- [ ] 不再呼叫工具、不出卡；訊息標「沒有回完」，已經出來的字留著，可以重試或問新的

### 8-3 重新整理
- [ ] 提議卡還在時重新整理：對話還在；地圖沒有提議；按卡的「在行程上看」用最新行程重新檢查
- [ ] 回覆到一半重新整理：那則標「沒有回完」，有「重試」

### 8-4 換裝置
- [ ] 電腦上問一句，手機登入同一個 LINE 帳號：對話接得上
- [ ] 另一位家人登入：看不到我的對話

### 8-5 長對話
一直在同一段對話裡問（可以重複第 1 部分）直到出現提示。
- [ ] 快滿：提示「這段對話快滿了」，還能問
- [ ] 滿了：輸入框停用，只留「開新對話」；舊訊息、「再看一次」照常；這時按詳情的「問 AI」自動開新對話並帶晶片

### 8-6 等待時間、費用
- [ ] 一般問題幾秒內開始出字；查好幾家的問題沒有一個一個慢慢查的感覺
- [ ] 記下幾個代表問題的大約秒數，和後台的用量
