## Review Focus

1. **一段交通沒有 `ready`／`transfers`（舊資料、指定分鐘、`basis: '指定'`）**：步驟、標籤、可以多待都不能當掉，缺的就不顯示 → Task 3 測 `compactSteps` 和 `slackHint` 吃只有 `rides` 的 Leg。
2. **班距型那一程的 `headwayMin`／`first`／`last` 是 null**：標籤寫「錯過 無下一班」或「約 ? 分一班」都不對，班距 null 時標籤只在 `ifMissed` null 時出現 → Task 3 測 `missBadge`。
3. **規劃那班在 `rideDepartures` 裡找不到**（巴士同時刻不同 trip、近鐵 tripId 對不上）：格子不能沒有「規劃」也不能標兩格 → Task 3 測 `departureCells` 用 tripId 對不到時改用發車時間。
4. **回住宿那段（`itemId` 是 null）的交通警告**：要出現在那段交通卡，不能掉到資料卡或消失 → Task 2 測 `leg: true` 且沒有 `itemId`；Task 4 用 `legWarnings` 找。
5. **手機行程在 `high` 時打開班次表**：要降到 `mid`，關掉不拉回；在 `low`／`mid` 不動 → Task 5 測 `snapForTimetable`。

**Interfaces（全部 export，Task 4～7 用）：**
- `rideShortName(ride: TransitRide, nameOfRoute?: (routeId: string) => string | null): string` —— 近鐵：「近鐵」＋`line` 的車種（「特急（往賢島）」→「近鐵特急」）；巴士：路線檔簡稱，`line` 去掉「（往…）」和第一個空白後的區間（「鷗巴士 5 號 鳥羽～國崎線（經相差）（往国崎）」→「鷗巴士 5 號」）；班距型：業者簡稱＋線名（`operator` 「JR西日本」+「大阪環狀線」→「JR 環狀線」；「南海電鉄」+「南海 機場急行」→「南海 機場急行」）。規則寫成小表＋通則，對不上就用 `line` 去掉括號。

- `legWarnings(day: DayPlan, entry: TimelineEntry): EngineWarning[]` —— 這段交通的警告：`leg: true` 且 `itemId === entry.itemId`；`entry.kind === 'lodging'` 時取 `leg: true` 且沒有 `itemId` 的。依等級排序（error、warning、info）。
- `warnCount(ws: EngineWarning[]): number` —— 只數 `error`、`warning`。
- `infoLines(leg: Leg, ws: EngineWarning[], slack: string | null): string[]` —— 點開後補充資訊框的行：警告文字（`ticket-tight`、`taxi` 不放；計程車的 `long-wait`／`bus-infrequent`／`transit-slow` 照原文），計程車加「每台起跳 {fareFromYen} 円（大型 {jumbo} 円）」（起跳價 null 不寫；大型的價錢從 `taxi.note` 取不到就只寫一般的），最後加 `slack`。
- `type MissBadge = { text: string; tone: 'hot' | 'muted' | 'bad' }`；`missBadge(ride: TransitRide, hotMinutes = 30): MissBadge | null` —— 照 spec §8.5 的表；`ifMissed` null →「錯過 無下一班」`bad`；班距型有值 →「約 {headwayMin} 分一班」`muted`（`headwayMin` null 時回 null）；有時刻表 → `lateMinutes ≥ hotMinutes` `hot`，否則 `muted`。
- `type CompactStep =`
  `| { kind: 'node'; time: string; name: string; wait: number | null; walk: number | null; walkLast: boolean; board: number | null; ticketTight: number | null }`
  `| { kind: 'ride'; index: number; mode: TransitRide['mode']; name: string; depart: string | null; minutes: number; badge: MissBadge | null }`
  `| { kind: 'transfer'; walk: number; elevatorWalk: number | null; note: string | null }`
- `compactSteps(leg: Leg, fromName: string, toName: string, nameOf: (id: string) => string, margin: number): CompactStep[]` —— spec §8.4：節點 `walk` 是從這個節點走到下一個節點的分鐘（出發點的 `walkBefore`、下車站的轉乘步行、最後下車站的 `walkAfter`），`walkLast` 是「走到終點」那段（畫「走 N 分」不加 ↓）；`board` 是在這裡上車的那一程 index（上車站才有）；`wait` 是在這裡等的分鐘（0 → null）；`ticketTight` 是買票站且空檔 < `margin` 時的空檔分鐘。轉乘有 `note` 或 `elevator === true` 時，在下車站和上車站中間插一個 `transfer`，那個下車站的 `walk` 改 null。班距型那程 `depart: null`。沒有 `ready`／`transfers` 時：等車用 `rides[i].depart − 前一程 arrive`，轉乘步行當 0。
- `slackHint(leg: Leg, margin: number): string | null` —— spec §8.7：只在第一程 `kind !== 'headway'` 且有 `ready` 時；N＝`depart − ready[0] − (isTicketRide(rides, 0) ? margin : 0)`；N ≤ 0 回 null；「前一站多待 {N} 分，一樣搭 {rides[0].depart}」。
- `type DepartureCell = { depart: string; arrive: string; kind: string | null; express: boolean; mark: 'plan' | 'next' | 'last' | null; gone: boolean; late: number | null }`；`departureCells(deps: RideDeparture[], ride: TransitRide, readyAt: string): DepartureCell[]` —— 規劃＝`tripId` 相同的那班，對不到時用 `depart` 相同的第一班；`next`＝`ride.ifMissed.depart` 那班（規劃之後第一班發車時間相同的），`late` 是 `lateMinutes`；`last` 是最後一班（同一格是規劃或下一班時，mark 留規劃／下一班，另外 `last` 用第二行顯示，所以改成 `isLast: boolean` 欄位也可以，實作決定，測試要涵蓋）；`gone` 是發車早於 `readyAt`；`kind` 是近鐵的車種（特急、急行、普通、快速急行、しまかぜ），`express` 是特急或しまかぜ。
- `firstCellIndex(cells: DepartureCell[]): number` —— 打開時要捲到的那格：規劃那列的前一列第一格（3 或 4 欄由呼叫的人給：`firstCellIndex(cells, cols)`）。
