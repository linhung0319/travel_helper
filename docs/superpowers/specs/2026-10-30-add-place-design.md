# T31 自己加地點：設計

2026-10-30，👤 和 Claude 討論定案。示意圖：<https://claude.ai/artifact/RdebWmZEi9Xjoc4KarL3zp>（私人連結，只有 👤 看得到）。

## 1. 目的

家人在 Google Maps、朋友推薦、旅遊文章看到我們資料裡沒有的地方（咖啡店、伴手禮店、集合點），要能**自己加進網站**，之後和一般的點一樣按想去、加到某天、排進行程、留言。

- 使用者有 5 位約 70 歲的長輩，多半在 LINE 內建瀏覽器打開。**操作要少、要看得懂**。
- interaction-design §8 原本只寫「透過 AI 加」（T16）。這次加上**自己動手**的路線；T16 的 AI 之後也走同一個確認畫面。

### 不做

- **不用 Google 的任何 API**（Places、Geocoding、Autocomplete）。原因：Places 的內容不能和非 Google 的地圖一起用（網站用 MapLibre）、要金鑰和計費。見 PLAN §3「2026-10-30 T26 暫定不做」。
- 不問營業時間、人數、價格、照片。自己加的點**沒有查過**，畫面上要講清楚。
- 類型不加「其他」：只有景點、餐廳、住宿（Worker 現在也只收這三種）。集合點之類的選「景點」。
- 不上傳照片。

## 2. 三種找位置的方法

都從**探索的搜尋框**進來（手機的探索頁、網頁右欄的探索分頁）。系統自己判斷輸入是哪一種：

| 輸入 | 怎麼判斷 | 怎麼找位置 | 名稱 |
|---|---|---|---|
| Google Maps 連結 | 網址的主機是 `maps.app.goo.gl`、`goo.gl`（`/maps/` 開頭）、`google.<tld>`（路徑 `/maps`）、`maps.google.<tld>` | 完整網址：瀏覽器直接解析。短網址：Worker 跟轉址拿到完整網址再解析 | 網址裡的 `/place/<名稱>/` |
| 日本地址 | 不是網址，而且有都道府県／市区町村／丁目的字樣，或「數字-數字」的門牌 | 國土地理院的地址搜尋 API（`https://msearch.gsi.go.jp/address-search/AddressSearch?q=`），瀏覽器直接查，取第一筆 | 空白，使用者自己填 |
| 其他文字 | 上面都不是 | 照常搜尋我們的資料；**找不到才**提議自己加，位置從地圖目前的中間開始 | 預填使用者打的字 |

### 搜尋框下面的提示（Claude 的決定）

- 不做浮動的下拉選單：提示是一塊**放在篩選列下面、清單上面**的區塊（`AddPlaceSuggest`），手機的探索頁和網頁的探索分頁都一樣。想去分頁不顯示。
- 輸入是連結或地址：清單照常會是空的，「沒有符合的地點」那行字不顯示，只顯示提示區塊（解析中 → 結果卡片：名稱、地區、「＋ 加這個地點」；或「已經有了」的那個點；或錯誤）。
- 輸入是其他文字：**用全部的點比對名稱（不看篩選、不看地圖範圍）**，一個都比不到才顯示「找不到「○○」」＋「＋ 自己加一個地點」＋教怎麼複製 Google Maps 連結。比得到但被篩選擋掉的，照舊顯示「沒有符合的地點，取消一些篩選看看。」
- 「已經有了」的判斷也一律用全部的點，不看篩選。

另外**在地圖上指**：網頁在地圖上按右鍵；手機在行程分頁的地圖（展開後）按住約 0.5 秒。跳出「在這裡加地點」，位置就是那裡，名稱空白。

### 解析 Google Maps 網址

座標的優先順序（前面的比較準）：

1. `!3d<緯度>!4d<經度>`：地點本身的座標（取最後一組）。
2. `/@<緯度>,<經度>,`：地圖畫面的中心，不一定在店上，但附近。
3. `?q=<緯度>,<經度>`、`?ll=`、`?query=`（是座標的話）。
4. `?q=`、`?query=`（`/maps/search/?api=1&query=` 也算）是**文字**時（Google Maps app 的「分享」短網址展開後常常是這種，例如 `?q=珈琲 灯台舎, 〒517-0011 三重県鳥羽市…&ftid=…`）：
   - 用第一個「,」「、」切開：前段當名稱；後段（拿掉郵遞區號 `〒nnn-nnnn`）如果像日本地址，就拿去查國土地理院，查到的座標當位置（精度同「地址」）。
   - 沒有逗號：整段當名稱；整段像地址的話也拿去查。
5. 都沒有座標：只拿到名稱，位置從地圖目前的中間開始，請使用者拖。

名稱：`/place/<名稱>/` 那一段 URL 解碼、`+` 換成空白；沒有 `/place/` 就用第 4 條的前段。都沒有就空白。

網址如果是 `consent.google.com/…?continue=<網址>`（從 Cloudflare 打過去可能先被轉到同意頁），用 `continue` 參數裡的網址解析。（以上兩條是審閱後 Claude 的決定。）

另外保留原始網址（短網址的話保留短網址，比較好看）存成 `links.googleMaps`，詳情的「在 Google Maps 開啟」用。

### Worker：展開短網址

- `GET /api/resolve-map-link?url=<短網址>`，要登入（和其他 `/api/` 一樣）。
- **只接受** `https://maps.app.goo.gl/…` 和 `https://goo.gl/maps/…`；其他回 400。
- 用 `fetch(url, { redirect: 'manual' })` 一路跟 `Location`，最多 5 次；每一跳的主機都要是 Google 的（`*.google.<tld>`、`*.goo.gl`、`*.app.goo.gl`），不是就停下並回 400。最後回傳 `{ url: <完整網址> }`。
- 不存任何東西。
- 本機只跑 `npm run dev`（假後端、沒有 Worker）時，短網址展開不了：畫面顯示「這種短網址要連上伺服器才能讀。可以改貼瀏覽器網址列的完整網址，或直接在地圖上指位置。」，還是可以按「自己加」。

### 已經有的點不重複加

解析出位置後，找**我們的資料點**（不含車站）和**沒刪除的自己加的點**：

- 距離 80 公尺內，而且名稱相符（正規化後互相包含，比對 `name.zh`、`name.ja`、`name.kana`、`name.en`），就當成同一個點：下拉選單顯示那個點的卡片（點了開詳情），不提供「加這個地點」。
- 名稱比對不到、但 30 公尺內有點：還是可以加，下拉選單多一行「附近已經有：○○」，可以點過去看。

## 3. 確認畫面

三種來源最後都到同一個確認畫面。欄位：

| 欄位 | 必填 | 說明 |
|---|---|---|
| 位置 | ✅ | 圖釘 |
| 名稱 | ✅ | 預填解析出來的名稱，可以改。存成 `name.zh`（使用者打的不一定是中文，但顯示一律用 `name.zh`）；從 Google Maps 解析出來的原名另外存在 `name.ja`（和 `name.zh` 一樣就不存） |
| 類型 | ✅ | 景點／餐廳／住宿三個膠囊，沒有預設，一定要選一個 |
| 備註 | | 一行字，例：朋友推薦，週三休 |

上方有一個小標籤寫來源：「從 Google Maps 連結」「從地址」「在地圖上指的」。下方的按鈕：「加進來，大家都看得到」。名稱或類型沒填時按鈕不能按。

### 手機

- 一整頁蓋在最上面（和詳情一樣用 `mobileStore` 的整頁層；返回 ‹ 關掉）。
- 上半約 45% 是**自己的一個小地圖**（新的 MapLibre 實例，同一個 OpenFreeMap 樣式；主地圖在別的分頁時是藏起來的）。**圖釘固定在畫面正中央，拖地圖對準**；地圖停下來時位置更新。上面浮一行提示「拖地圖，讓圖釘對準店門口」。
- 小地圖上照常畫我們的資料點（小圓點就好），讓人知道附近有什麼。
- 下半是表單。鍵盤打開時表單要捲得到按鈕。

### 網頁

- 表單放在**右欄**，取代探索清單（上方 ‹ 返回探索）。
- **圖釘放在中間的主地圖上**，可以用滑鼠拖。地圖飛到那個位置（縮放到 16）。
- 按右鍵加地點時，右欄直接換成表單。
- 表單開著時，點地圖上別的資料點**不開詳情**（避免誤觸），右鍵改成「把圖釘移到這裡」。
- 取消或加完，右欄回到探索清單、主地圖的圖釘拿掉；加完的話地圖上那個新點閃一下（`commands.focus`）。

## 4. 加好之後怎麼呈現

自己加的點要和我們查過的點一起出現在所有列表和地圖上，但**看得出來不一樣**：

- **地圖**：照類型的圖標，但外框是虛線、白底（interaction-design §8）。名稱標籤照常。
- **探索清單、想去清單、照片牆**：卡片虛線框，照片位置用類型色塊加圖示（和沒有照片的點一樣），副標寫「自己加的 · <加的人>」，沒有評分、沒有分級。
- **篩選**：類型、地區照常（地區由座標算：落在哪個 `areas.json` 的 bbox 裡就是那一區，都不在就沒有地區）。分級、團體人數這些篩選：自己加的點不符合（因為不知道）。投票的篩選照常。
- **排序**：推薦排序排在我們的點後面；距離排序照常。
- **詳情**（手機整頁、網頁彈窗都用 `PlaceDetail`）：
  - 標題旁「自己加的」虛線膠囊；下一行「<加的人> 加的 · <日期>」。
  - 黃色提示框：「我們沒查過這個點：營業時間、能不能坐 15 人都不知道。排行程時只用位置估交通時間。」
  - 備註（有的話）。
  - 有 `links.googleMaps` 就有「在 Google Maps 開啟 ↗」；沒有就用座標組一個 Google Maps 的網址。
  - 想去、加到某天、留言、問 AI 照常。
  - 「✎ 修改」：打開同一個確認畫面（手機整頁、網頁右欄），預填現在的值；名稱、類型、位置、備註都能改。**誰都能改**（全員共用，architecture §3.1）。類型能改要動 Worker：`PATCH /api/user-places/:id` 多收一個選填的 `type`（同樣只收三種），沒給就沿用（Claude 的決定）。修改時保留 `links`、`addedVia` 不動。
  - 「刪除」：**只有加的人看得到**。按了先確認（網站自己的對話框，不用 `confirm()`）。
  - 分頁：簡介、位置、留言（沒有評論分頁；簡介只有上面這些）。
- **刪除之後**：軟刪除。各列表、地圖都不再顯示。已經排進行程的話，那一格照常顯示名稱，但有「這個點已刪除」的警告，由排行程的人自己拿掉；候選裡的那筆直接不顯示。
- **行程引擎**：把沒刪除和已刪除的自己加的點都交給 `placeLookup` 的 `users`；已刪除的標成 `retired`（引擎要讓 `users` 也能帶 retired，警告文字照下架的點）。

## 5. 資料與同步

- 後端的 `user_places`（T24）的資料表不改，API 只加 PATCH 的 `type`（§4）：`POST /api/user-places { type, data }`、`PATCH /api/user-places/:id { data }`、`DELETE /api/user-places/:id`（只有本人）、`GET /api/user-places?since=`。
- `data` 的形狀（Worker 只檢查名稱、座標）：

  ```json
  {
    "name": { "zh": "珈琲 灯台舎", "ja": "珈琲 灯台舎" },
    "coords": [136.8431, 34.4815],
    "note": "朋友推薦，週三休",
    "links": { "googleMaps": "https://maps.app.goo.gl/Pq7…" },
    "addedVia": "google-link"
  }
  ```

  `addedVia`：`google-link`／`address`／`map`／`search`（打名稱找不到）／`ai`（T16 用）。
- **前端的 `Backend` 介面加上**：`listUserPlaces()`、`createUserPlace(type, data)`、`updateUserPlace(id, data)`、`deleteUserPlace(id)`、`resolveMapLink(url)`；`SyncState` 加 `userPlaces`。假後端（`mock.ts`）照 Worker 的規則實作（ID `user-<12 碼>`、只有本人能刪、軟刪除），`resolveMapLink` 在假後端丟「要連上伺服器」的錯誤。T15 串接時換成真的 API。
- **自己加的點要轉成網站的 `Place`**，合併進 `dataStore.places`（和預設資料一起），所以所有列表、地圖、搜尋、詳情不用各自處理。`Place` 加一個欄位標來源（例如 `origin: 'base' | 'user'`，和 engine 一樣），加的人、建立時間、備註、`addedVia` 也放進去。
- 同步：和投票、留言一樣每 30 秒看 `sync` 的版本，變了才重抓。

## 6. 其他

- 地圖的右鍵、按住：只在沒有其他彈窗、不在拖曳行程卡片時有效。
- 錯誤的講法：
  - 地址查不到：「找不到這個地址。可以改打大一點的範圍（例如只打到町），或直接在地圖上指位置。」
  - 網址看不懂：「這個連結讀不到位置。可以在地圖上指位置，名稱自己填。」
  - 存不了（網路）：留在確認畫面，顯示錯誤，可以再按一次。
- **文件**：interaction-design §8 加上自己動手的路線；architecture §4 的 API 表加 `resolve-map-link`；architecture §2 記 `Place` 的新欄位和新元件。

## 7. 測試與完成條件

- 單元測試：
  - Google Maps 網址解析：`!3d!4d`、`@`、`?q=` 座標、`?q=` 文字（名稱＋地址）、`/maps/search/?api=1&query=`、`consent.google.com` 的 `continue`、只有名稱、看不懂的網址；名稱的 URL 解碼。
  - Worker 的 PATCH 帶 `type` 會改類型、不給就沿用、不認得的類型 400。
  - 輸入分類：連結、地址、其他文字。
  - 重複判斷（80 公尺＋名稱、30 公尺的「附近已經有」）。
  - Worker 的 `resolve-map-link`：只收 Google 短網址、轉址到別的網域會擋、最多 5 次、要登入（`fetch` 用假的）。
  - 假後端的 user places：新增、修改、只有本人能刪、軟刪除、sync 版本會變。
  - 自己加的點轉成 `Place`、地區由座標算。
  - engine：`users` 帶 retired 時發下架的警告。
- Playwright（手機、電腦尺寸各一次）：
  - 貼完整的 Google Maps 網址 → 確認 → 存 → 探索清單出現虛線框的卡片、地圖上有點 → 開詳情看得到「自己加的」和提示框。
  - 打地址（攔截國土地理院的請求回假資料）→ 存。
  - 網頁右鍵加地點；手機在行程地圖按住加地點。
  - 修改名稱；本人看得到刪除、別人看不到；刪除後列表不見。
- 完成條件：上面的測試都過；`npm test`、`npm run typecheck` 通過；手機和電腦尺寸的截圖給 👤 看過。
