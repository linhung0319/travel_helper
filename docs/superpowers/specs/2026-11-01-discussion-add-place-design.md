# T33 討論彈窗、加地點入口、上一步：設計

2026-11-01，👤 和 Claude 用草圖討論定案。草圖：<https://claude.ai/artifact/4kcTHAFyzpYZwfcMVsPqZJ>（私人連結，只有 👤 看得到）。這份和舊規格衝突的地方，以這份為準。

## 1. 為什麼改

- **討論和行程斷開**：討論藏在網頁的頭像選單、手機的「我」，大家看行程時想到的事沒地方寫。手機的討論寫死整趟，留不了「這天」；網頁選「整趟」時也不能換天。
- **加地點找不到**：沒有常駐按鈕。只有搜尋完全比不到才出現、網頁地圖按右鍵、手機按住地圖；搜尋框的提示字也被截斷（手機只看得到「搜尋名稱、貼」）。
- **編輯條的快照很難用到**：大多數人改錯只會想退一步，但現在沒有上一步。

## 2. 討論按鈕：跟著「問 AI」

放在「問 AI、編輯」同一排，**只有圖示和數字，沒有文字**。樣式永遠和問 AI 一樣；要凸顯的是「編輯」和「完成」。

| 畫面 | 這一排 |
|---|---|
| 手機，平常 | `2/5 週五`、問 AI（白）、💬 3（白）、編輯（藍底） |
| 手機，編輯中 | `編輯 2/5`、✦、💬 3、↩、完成（白底）；✦、💬、↩ 是墨色條上的白字 |
| 手機，整趟 | `整趟行程`、問 AI、💬 2 |
| 網頁，平常 | `2/5 週五・鳥羽`、問 AI、💬 3、編輯（藍底） |
| 網頁，編輯中 | `編輯 2/5（五）`、問 AI、💬 3、↩、完成（白底） |
| 網頁，整趟 | `整趟行程`、問 AI、💬 2 |

- **描述文字縮短**：網頁拿掉「第 N 天」。手機只留星期，寬度夠才顯示地區，放不下自動省略（實測 360 寬時，日期和說明只剩約 80，剛好放滿；更窄時只剩日期）。
- **網頁編輯中**：問 AI、討論搬進編輯條，拿掉下面重複日期的那一列，省下一列給時間軸。「第 N 版」拿掉，只有存檔時才顯示「儲存中」。
- **數字**：還沒看過的留言數；沒有新留言時只有圖示。記每台裝置上次打開討論的時間（localStorage），別人在那之後的留言算新的，自己的不算；新裝置第一次打開時舊留言全算已讀。
- **不在行程分頁時**：「行程」分頁（手機底部、網頁右欄）帶紅點。
- 頭像選單和「我」拿掉「討論」。行程的卡片、時間軸**一行都不加**（👤 決定：垂直空間珍貴）。代價是看行程時不知道哪張卡有人留言。手機面板拉到最低時看不到按鈕，拉上來才有。

## 3. 討論彈窗

網頁、手機同一份內容（新元件，取代 `MapPanel` 的留言內容和手機的討論整頁）。

- **網頁**：浮在地圖上（現在 `MapPanel` 的位置）；✕、Esc、點地圖關掉。
- **手機**：大彈窗，蓋住約 93% 的高度，上面露出一條。右上角大 ✕（36px 圓，點擊範圍至少 44px）、點上面露出的那條、往下拉把手、返回鍵都能關（佔一筆 history，和其他整頁一樣）。

### 篩選

一排晶片：全部、整趟、2/2 … 2/13。手機橫捲，網頁換行。有新留言的日期帶小紅點。

- **全部**：有留言的對象都列（整趟、日期、資料點），最新留言的排最上面。還沒排進行程的點只在這裡出現，標「還沒排」。
- **整趟**：只有整趟的討論，直接展開。
- **某一天**：「這天的討論」**置頂**（沒有留言也列）；接著是這天有留言的點，含候選和住宿，依最新留言排；最下面「這天還沒人留言的點」，點了可以留第一則。車站、航班沒有留言，不列。
- **預設**：行程選了某天就開那天；選整趟就開「全部」。

### 以對象為單位

- 收起來：名稱、在哪天（`2/4 09:30`、`2/4 候選`、`還沒排`、`已不在行程`）、留言數、最新一句、有沒有新留言。左邊的色條是類型色，日期和整趟是芥子黃。
- 一次只展開一個。展開後由舊到新，最新的一則緊貼輸入框。
- 資料點展開後多「看詳情」和「到行程看」（關掉彈窗、換到那天、選中那張卡）。

### 留言綁在哪裡

留言的 `target` 已經支援地點、`day:<日期>`、`trip`，**資料結構和後端都不用改**；留言都同步到前端（`sharedStore.comments`），分組是前端的純函式。

- 點換到另一天：留言跟著點，出現在新的那天底下。
- 點移出行程：留言還在，在「全部」標「已不在行程」。
- 日期的留言永遠留在那天。這是分開「日期留言」的原因。
- 同一個點排在兩天：兩天底下都看得到同一串。
- 詳情的「留言」分頁、想去清單第三行的最新留言都保留，是同一串留言。

### 輸入框和鍵盤

- 只有一個輸入框，**固定在彈窗底部**，上面寫「留給：鳥羽水族館」，跟著展開的對象換。沒有展開時：選某天是留給那天，選整趟或全部是留給整趟。
- 手機鍵盤彈出時：彈窗縮到鍵盤上方（現有的 `--kb`，`lib/keyboard.ts`），收起晶片和上面露出的那條，捲到最新一則。輸入框 16px（architecture 的規則，iPhone 才不會放大）。
- 打到一半關掉，草稿保留（每個對象一份，只存在記憶體）。
- 只有一層，不做回覆串、不做 @ 人。

## 4. 加地點

### 入口

**只有清單標題列的「＋ 加地點」**，在探索的「597 個地點」那一列（網頁、手機都是）：`597 個地點`、`＋ 加地點`、`問 AI`。想去分頁不放。

搜尋列已經放滿（手機搜尋框 154、網頁 184），放進去要把篩選、排序改成只有圖示。手機往下捲時這一列會捲走，要捲回最上面才按得到；加地點不常用，接受這個代價。

- 搜尋框提示字改回「搜尋名稱」，不再判斷連結和地址（拿掉方法 1）。
- 不在清單最後加一行（拿掉方法 3：資料點太多，捲不到最下面）。
- 比不到任何結果時，顯示一行「找不到，＋ 自己加」，打開同一個彈窗並帶入打的字。
- 地圖右鍵、手機按住地圖保留，畫面上看不到，改開同一個彈窗並帶入位置。

### 彈窗

網頁、手機同一個流程。網頁原本表單佔右欄、圖釘在主地圖，改成彈窗裡的小地圖（手機 `AddMap` 的做法）。編輯自己加的點（「✎ 修改」）也用這個彈窗。

1. **輸入**：一個輸入框「貼 Google Maps 連結或日本地址」，加三步驟的說明和「在地圖上指位置」。判斷沿用 `lib/addPlace/suggest.ts`。
2. **找到了**：小地圖（圖釘固定在正中央，拖地圖對準）、名稱、類型、備註，最下面**「確定加入」**和一行「加了之後大家都看得到」。按了才存。
   - 名稱、類型沒填不能按。類型沒有預設，連結也判斷不出來。用地址找到時名稱是空的。
   - 已經有這個點：不給確定，顯示那個點的卡片和「看這個地點」（沿用 `findExisting`）。
   - 找不到：留在第一步顯示原因，「在地圖上指位置」直接到第二步。
3. 手機鍵盤彈出時，彈窗一樣讓出 `--kb`，輸入中的欄位和「確定加入」捲得到。

AI 加地點（`addPlaceStore.start({ via: 'ai' })`）直接到第二步。

## 5. 探索、想去的篩選列

- **網頁也把類型拉出來**：搜尋列下面一列「全部、景點、餐廳、住宿」，和手機共用 `TypeChips`。照片牆／清單切換也搬到這一列（和手機一樣），搜尋框多出約 96 的寬度。
- 「篩選」面板裡的類型拿掉（手機已經沒有）。
- **套用的篩選晶片不再顯示，網頁、手機都一樣**：要看條件就點「篩選」，按鈕上有數字（不算類型）。
- AI 一次套多個類型時，類型列把選到的都標亮（現在是靠晶片表達）。「AI 挑的」結果條照舊。
- 取代 §0「AI 用的條件要看得到」原本靠晶片的做法：看篩選按鈕的數字，點開面板看條件。

## 6. 快照和上一步

| 項目 | 決定 | 說明 |
|---|---|---|
| 編輯條的「快照」按鈕 | 拿掉 | 編輯時幾乎用不到 |
| 上一步 ↩ | **新增** | 編輯條上一直都在 |
| 每次修改自動存一份 | 保留 | Worker 存檔時順手做，後端不動 |
| 版本清單和復原 | 保留，移位置 | 改名「過去的版本」，放到頭像選單和「我」的「下載行程」旁邊；復原有自己的確認，不用先進編輯 |
| AI 打開版本清單 | 保留 | `show_screen` 的 `snapshots`；還是由使用者自己按復原 |
| 修改後提示裡的「復原」 | 保留 | 和上一步做同一件事 |

**為什麼不能全拿掉**：行程只有一份，15 個人都能編輯，「編輯」只是防誤按。有人刪掉一天的內容、隔天才發現，或要救的是別人的修改，上一步都做不到。

**上一步的規則**：

- 範圍是這次編輯裡自己改的。按「完成」、閒置自動結束後清空。
- 別人改過（`version` 不是自己最後存的那版）就不能退，提示「行程已經被改過，不能復原」，和現在的復原一樣。
- 每個 `changeItinerary` 都算一步，包括現在沒有復原的：停留時間、交通方式、固定開始時間、清掉住宿、設為主要、移到別組、標籤。
- 有 `undo.after` 的動作（把候選加回去）要一起退。
- 沒有可退的時候按鈕變灰。退一步本身不算一步。

## 7. 不做

- 行程卡片上的留言數和留言按鈕。
- LINE 通知（要動 Worker，等紅點用過再說）。
- 從行程直接加新地點成為候選。
- 版本清單按日期和人分組（這次只移位置）。

## 8. 完成條件

手機（390、360）和網頁（1280）都跑 Playwright：

1. 討論按鈕在這三個畫面的位置和樣式對（平常、編輯中、整趟），360 寬不換行、沒有橫向捲動。
2. 彈窗：全部、整趟、某一天的列法；日期留言置頂；展開看到全部留言；「留給」跟著換；留在日期、地點、整趟的都存對 target。
3. 點換天、移出行程後，留言在對的地方。
4. 手機：鍵盤高度（設 `--kb`）下輸入框看得到；✕、點外面、返回鍵都能關；草稿還在。
5. 未讀數字：別人留言後增加，打開後歸零，自己的不算。
6. 加地點：按鈕打開彈窗；連結、地址、地圖三條路；沒按「確定加入」不存；已有的點不給確定。
7. 網頁有類型列；兩邊都沒有套用晶片；篩選按鈕的數字對。
8. 上一步：連退多步、沒有復原提示的動作也能退、別人改過不能退、結束編輯後清空；版本清單從頭像選單、「我」打得開，不進編輯也能復原。
9. `npm run typecheck`、`npm test`、整包 e2e 通過。舊的 e2e 依賴 `filter-applied`、`snapshots-button`、`account-comments`、`m-me-comments`、`add-suggest` 的要跟著改。
