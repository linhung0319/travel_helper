# 可用性走訪：根本原因歸納（2026-11-06）

來源：`docs/ux-review/report.md`（結論）和 `synthesis.md`（16 條問題、8 條衝突、9 條正面）。
做法：報告裡的「方向」「建議」一律不採用，先還原成使用者當時想做什麼、在哪裡卡住，再歸納。
範圍：探索分頁選了一區之後的畫面（地區頁 → 清單 → 詳情 → 想去）；志摩、鳥羽。

記號：R1m／R1d＝角色一（不耐煩的初次使用者，約 65 歲）手機／電腦；R2＝角色二（被分派看住宿的家人，手機）；R3m／R3d＝角色三（排行程的主辦）。

---

## 0. 這個頁面的核心任務

**一個家人打開「志摩」，看出這裡有哪些可以玩、吃、住的地方，挑出自己想去的標起來，而且確定其他家人看得到。**

附帶但不是核心：主辦把看到的點排進某一天（基準路徑，R3）。

## 2. 多個角色在同一個地方卡住的（最強的訊號，優先）

1. **「志摩只有 5 個景點」**：三位、三個版面全部得到錯誤的總數（P1）。這是觸發走訪的那個問題。
2. **退不回去**：三位都在「清單 → 地區頁」或「詳情裡再開詳情 → 退」這兩處迷路，角色一兩次、角色二一次列入最卡前三（P4）。
3. **按了想去之後不確定發生了什麼**：三位都碰到回饋不一致（P6）；角色一兩個版面都被紅心嚇到（P2）。
4. **換區時被丟進清單**：角色一、角色二共三個版面（P3）。
5. **符號和詞看不懂**：◎○△✕—、「書架」「候選」三份紀錄都列（P11、P16）。

## 3. 根本原因

### 根本原因 1：畫面從不告訴使用者「你現在看到的是全部的哪一部分」

**一句話**：每一層都只顯示「挑出來的那些」和它的數量，卻沒有任何地方寫出母體有多少、挑的規則是什麼、沒挑進來的去了哪裡；使用者只能把看到的數字當成全部。

**解釋哪些問題**
- P1（R1m、R1d、R2）：「全部 5」「5 個地點」「志摩 5」三個數互相印證，沒有一處寫 24；B 級 19 個沒有入口；「S、A 級景點」這行規則沒人讀懂，所以沒人知道這是一部分。
- P1 反向（R1d、R1m）：兩排書架重疊，沒說「這 3 個就是上面那 3 個」，數成 6 個。
- P8（R1d）：每段只露 3 張，通往其餘的門是小灰字，看不到門就以為那段只有 3 個。
- P9（R2）：附近每類只列 3 個、沒有「還有幾個」；某一類沒出現，分不出零還是沒顯示。
- P3 的灰數字（R1m、R1d）：地區分頁冒出「志摩 5、鳥羽 9」，沒說這是「目前這個篩選在那裡有幾個」。
- R2 2a 的「一間住得下全團」：不知道是自己選的還是預設就開著，所以不知道 32 間是不是全部。
- P14（R1m）：子地區列右邊被切掉，看不到的就不存在。

**從根本解決要動的層級**：**資訊架構**（「母體 → 挑出來的子集 → 其餘」這個關係要成為畫面的結構，不只是補一行字）；連帶動布局（分母、入口要放在數字旁邊看得到的位置）。

### 根本原因 2：使用者在畫面之間的位置和退路是不可預測的

**一句話**：畫面之間的層級關係沒有被表達出來，「‹」「地區分頁」「瀏覽器上一頁」每次退的結果都不同，而且換區會把看不見的狀態（篩選、書架）一起帶走，所以使用者不知道自己在哪一層、也不知道怎麼回去。

**解釋哪些問題**
- P4（R1m、R1d、R2）：「‹」退一層或兩層、再點「志摩」沒反應、上一頁沒反應，最後靠看不懂的「‹ 書架」賭一把。
- P3／C2（R1m、R2）：點「鳥羽」預期是鳥羽的首頁，卻跳進沿用志摩篩選的清單；篩選是隱藏狀態，換區時跟著走但沒說。
- P7（R2、R1m）：到了新畫面卻停在中間，分不出「這是新畫面」還是「剛才那份往下捲了」。
- P10（R1d）：同一種東西（詳情）從照片開和從地圖開出現在不同地方，✕ 位置不同。
- P16 的「書架」（三位）：這個詞是唯一的返回入口，卻沒有人知道它指哪一層。
- P13 的一部分（R3m）：編輯中從探索開的詳情和從行程開的詳情功能不同，連主辦也要來回找。

**從根本解決要動的層級**：**操作流程**（每個動作退到哪裡要固定，換區要不要帶狀態要明確）加**資訊架構**（層級要能被看見：我在志摩 › 一定要去 › 橫山展望台）。

### 根本原因 3：動作的結果和目前的狀態沒有用使用者的話說清楚

**一句話**：想去、候選、排進行程是三種不同的狀態，但畫面用同一顆紅心、同一個數字、消失的提示和內部用語（候選、排了、◎）來表達，使用者按下去之前不知道會動到什麼、按完不知道動到了什麼、也不知道這是誰的。

**解釋哪些問題**
- P2（R1m、R1d）：紅心一開就是紅的（別人按的），分不出「有我」還是「沒我」；按下去變成取消，而且沒提示；實際動到了別人的資料。
- P6（R1m、R1d、R3m）：有時有提示、有時沒有；徽章數的是候選、愛心按了不變；想去頁用「已排進行程 · 2/5 排了」描述自己剛標的點。
- P12（R1d、R1m、R3）：「加到某天」讓人以為會動到行程，實際只是候選，畫面沒說。
- P11（R2、R1d、R1m）：◎○△✕— 沒有圖例；「15 人 ◎」配「沒有資料」，符號和理由矛盾。
- P16 的「候選」「排了」「👎 0」「S／A／B」（三位）：內部用語直接露出。
- C4：想去是「我的清單」還是「全家的計數」，畫面沒有區分，兩種讀法都說得通。

**從根本解決要動的層級**：**操作流程**（按下去的語意、確認和復原的方式、第一次出現時的說明）加**視覺細節**（我的／別人的要長得不一樣；符號要配字；無資料要是空白不是 ◎）。

## 5. 不能改壞的（走訪的正面發現，原型要保留）

- 點照片／卡片就進詳情、點「全部 N ›」就列出，沒有人卡過（G1）。
- 玩、吃、住分開的書架，兩位角色一都偏好；41 家餐廳攤開是「字太多，眼睛滑過去」（G2、C1）。
- 子地區晶片一點就縮小、數字跟著變，三版面都一步做到（G3）。
- 詳情「位置 → 附近」兩步到，有走路分鐘和全員乘 1.4（G4）。
- 詳情的費用直接算好 15 人、「15 人」方塊一句話說能不能住（G5）。
- 「✓ 已加到想去，家人也看得到」出現時兩位角色一都信了（G6）。
- 單層的詳情 → 清單返回停在原位是對的（G7）。
- 「2 月注意」紅字和「二月休」標籤有被看到並用上（G9）。
